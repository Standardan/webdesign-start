# /webdesign-start — Guided web design discovery & build

Read the file `webdesign-start/SKILL.md` in this project (if it is not at the project root, locate the `webdesign-start` folder — it may live in `.cursor/`, a `skills/` directory, or the repo root) and follow its workflow exactly, starting at Phase 0.

Summary of what you are signing up for: on every invocation check this skill and the live beUI registry/upstream skill for updates; run a short adaptive discovery questionnaire (batches of 3-4 multiple-choice questions); inspect user-provided example sites before researching more; turn approved traits and automatically selected live components into a Reference Translation Matrix plus Component Opportunity Map inside `DESIGN-BRIEF.md`; and only then build a reference-driven style sample using the highest-impact beUI selection before the full site. Do not present a component picker: use the strongest compatible beUI match by default and revise only when the user critiques the rendered result. Finish with an honest fidelity and component-coverage review.

Do not skip the questionnaire, the research phase, or the brief-approval gate — the entire value of this command is removing ambiguity before code is written.
