# /webdesign-start — Guided web design discovery & build

Read the file `webdesign-start/SKILL.md` in the current project (if it is not at the project root, locate the `webdesign-start` folder) and follow its workflow exactly, starting at Phase 0.

Summary: on every invocation rebuild a complete live inventory with exact counts and every current identifier from all component/resource sources; run a short adaptive discovery questionnaire (batches of 3-4 multiple-choice questions presented as lettered options); inspect user-provided example sites before researching more; and turn approved traits plus automatically selected components into a Reference Translation Matrix and Component Opportunity Map inside `DESIGN-BRIEF.md`. Give no catalog priority: for every designed surface, compare the strongest viable candidate from every catalog, implement the best fit through direct use, adaptation, or composition, and never ship plain UI with no observable catalog lineage. Confirm the direction in a reference-driven style sample before the full site, revise from user critique, and finish with an honest fidelity, inventory, and component-coverage review.

Do not skip the questionnaire, the research phase, or the brief-approval gate — the entire value of this command is removing ambiguity before code is written.

If web search is unavailable in this environment, use the curated anchor library inside `webdesign-start/references/research.md` and tell the user the examples come from a curated list rather than a live search.
