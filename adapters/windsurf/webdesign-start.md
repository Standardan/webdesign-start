---

Read the file `webdesign-start/SKILL.md` in this project (locate the `webdesign-start` folder if it is not at the root) and follow its workflow exactly, starting at Phase 0.

Summary: harvest what the user already said, let the user describe it in their own words, show an exploration spread of 8 very different ideas for their subject, settle the register (world, product launch, or dashboard/app), keep private hypotheses about what kind of site it should be (`references/formats/index.md`), and ask the plain-language questions that best split them, plus the business's particulars and its world (Phase 1). Invent three genuinely different concepts and let the user pick (Phase 2). Write a dense Creative Direction Paragraph with exact palette, type treatment, a hero made for the site, key components, section devices and domain-verb interactions, plus the fixed Quality Contract, into `DESIGN-BRIEF.md`, and get approval (Phase 3). Build and screenshot-review the first frame at 1440×900 and 390×844 before the full build (Phase 4). Build every section with its own device (Phase 5), then run the polish pass on the whole page: chrome, every frame, type, controls, rendering detail, rhythm (Phase 6). Then check that every promise in the brief exists, get a cold critique, and review the renders against the paragraph slot by slot until nothing is left to fix (Phase 7). Sites are contemporary by default and built with beautiful modern components, always restyled to the concept; never stock imagery or components left in demo styling. The build mode (single file or project) is asked each time. Never invent testimonials, metrics or reviews.

Do not skip the concept step, the direction-approval gate, or the screenshot review.
